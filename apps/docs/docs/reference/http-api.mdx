All paths are relative to `basePath` (default `/api`). Dates are ISO 8601, or Unix milliseconds on the `Query` objects used in code. Time zones are IANA names and default to the site's time zone. Intervals are `hour`, `day`, `week` or `month`.

## Public routes

CORS is open and `text/plain` bodies are accepted, so the browser sends events without a preflight request.

| Method and path                    | Auth                | Description                                                                                                                                                                                                                                    |
| ---------------------------------- | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /event`                      | none                | Tracker payload, see below. 202 on accept and on a filtered bot. 400, 403, 404 or 413 otherwise. 8 KB at most.                                                                                                                                 |
| `POST /attribution`                | none                | Returns `{ visitorId, sessionId }` computed on the server for this request. Rate limited per hash.                                                                                                                                             |
| `POST /v1/payments`                | Bearer site API key | Body: `PaymentInput`. Idempotent on `(siteId, id)`. Answers `{ ok, duplicate, payment, attributed }`.                                                                                                                                          |
| `POST /v1/bots`                    | Bearer site API key | Body: `{ requests: [{ userAgent, path, ts? }] }`, at most 500. Answers `{ ok, recorded, skipped }`. See [Bot traffic](/guides/bot-traffic).                                                                                                    |
| `POST /v1/annotations`             | Bearer site API key | Body: `{ text, ts? }`. Adds a dated note to the charts. `ts` is Unix ms or an ISO 8601 date, default now; `text` at most 200 characters. Answers 201 `{ ok, note }`. See [Notes on the chart](/guides/dashboard-embedding#notes-on-the-chart). |
| `POST /v1/goals`                   | Bearer site API key | Body: `name`, optional `props`, and `visitorId` or `email`.                                                                                                                                                                                    |
| `POST /webhooks/:provider/:siteId` | signature           | `provider` is `stripe`, `dodo`, `lemonsqueezy`, `paddle`, `polar`, `razorpay`, `creem` or `gumroad`. Verified with the site's webhook secret.                                                                                                  |
| `POST /v1/cron`                    | Bearer cron secret  | Runs the scheduled email work: the summary if due and tracker-down alerts. Answers `{ ok, summary, down }`. 401 without the `email.cronSecret`. `GET` works too. See [Email notifications](/guides/email-notifications).                       |
| `GET /health`                      | none                | Health check.                                                                                                                                                                                                                                  |

### Event body

The body is a `TrackerPayload`, compact on purpose, to keep the request small:

| Key   | Type                                                            | Meaning                                                                                                |
| ----- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `w`   | string                                                          | Site id. Required.                                                                                     |
| `t`   | `pageview`, `goal`, `outbound`, `ping`, `identify` or `revenue` | Event type. Required.                                                                                  |
| `u`   | string                                                          | Page URL. Required.                                                                                    |
| `r`   | string                                                          | Referrer.                                                                                              |
| `vid` | string                                                          | Visitor id. Only needed in `persistent` mode.                                                          |
| `sid` | string                                                          | Session id. Only needed in `persistent` mode.                                                          |
| `sw`  | number                                                          | Screen width.                                                                                          |
| `n`   | string                                                          | Goal or event name.                                                                                    |
| `p`   | object                                                          | Properties: strings, numbers, booleans or null.                                                        |
| `d`   | number                                                          | Engaged time in milliseconds.                                                                          |
| `a`   | number                                                          | Revenue amount, major units (19.99).                                                                   |
| `c`   | string                                                          | Currency.                                                                                              |
| `o`   | string                                                          | Order id. `revenue` events are de-duplicated by it.                                                    |
| `m`   | `strict`, `enriched` or `persistent`                            | Privacy mode of the tracker. Without it the event is treated as `strict`, and `vid`/`sid` are ignored. |

```bash
curl -X POST https://analytics.example.com/api/event \
  -H 'Content-Type: text/plain' \
  -d '{"w":"SITE_ID","t":"goal","u":"https://example.com/pricing","n":"signup","p":{"plan":"pro"}}'
```

## Admin routes

Admin routes need a session cookie from `POST /auth/login`, or `Authorization: Bearer <admin token>`. Without one they answer 401.

### Auth

| Method and path     | Description                                            |
| ------------------- | ------------------------------------------------------ |
| `POST /auth/login`  | Body `{ "password": "..." }`. Sets the session cookie. |
| `POST /auth/logout` | Clears it.                                             |
| `GET /auth/me`      | Whether the current request is authenticated.          |

### Email

| Method and path    | Description                                                                                                                                                                                  |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /email`       | `{ configured, to, settings }`: whether the server has an `email` sender, its default recipient and the saved `EmailSettings` (`to`, `payments`, `summary`, `hour`, `down`, `timezone`).     |
| `PUT /email`       | Saves the fields sent and keeps the rest. 400 for an invalid address, frequency (`off`, `daily`, `weekly`), hour (0 to 23) or time zone. Answers the saved settings.                         |
| `POST /email/test` | Sends a test message to `to` from the body, else the saved or default recipient. Answers `{ ok, to }`; 400 without a sender or address, 502 with the sender's error message when it refuses. |

### Preferences

| Method and path    | Description                                                                                                                      |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| `GET /preferences` | The dashboard settings (overview layout, summary numbers and chart, live refresh) as one JSON object; `{}` before any are saved. |
| `PUT /preferences` | Replaces them with the JSON object in the body. The server stores it as is; the dashboard checks each value when it reads it.    |

### Sites

| `GET /summary`               | Every site's visitors, revenue and orders in `from`–`to` (ISO dates, default the last 24 hours) and who is online now, as `SiteSummary[]`. ### Statistics

All take `from`, `to`, `interval`, `tz` and filters. `GET /sites/:id/realtime` takes none of them.

`overview`, `timeseries` and `breakdown` also take `compare=previous` (the period of the same length just before) or `compare=year` (the same dates a year earlier). The comparison comes back in the same response: every `TimeseriesPoint` and `BreakdownRow` gets a `previous` object (the bucket at the same position, matched by index; the row's numbers, all 0 when the value had no visits), and `overview` measures its changes against that period. Without `compare` nothing extra is read, and with it every one of these requests reads the data twice, so leave it off on a dashboard you keep open all day on a database that bills rows read.

| Method and path                       | Returns                                                                                                                                                             |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /sites/:id/overview`             | `Overview`. Revenue counts only the site's currency; the rest is in `otherCurrencies`.                                                                              |
| `GET /sites/:id/timeseries`           | `TimeseriesPoint[]`: traffic, revenue, orders and rates per bucket                                                                                                  |
| `GET /sites/:id/breakdown?dimension=` | `BreakdownRow[]`                                                                                                                                                    |
| `GET /sites/:id/bots`                 | `BotStats`: crawler requests, filtered by repeated `crawler`, `category` and `page`                                                                                 |
| `GET /sites/:id/vitals`               | `VitalsResult`: the 75th percentile of Core Web Vitals for the site and its pages with the most reports, over the range (admin only)                                |
| `GET /sites/:id/journeys`             | `JourneysResult`: where sessions go over up to four steps, from the newest 5,000 sessions of the last 30 days of the range (admin only)                             |
| `GET /sites/:id/retention`            | `RetentionResult`: weekly cohorts of new visitors and how many came back, at most 12 cohorts (admin only; empty unless the site uses the `persistent` privacy mode) |
| `GET /sites/:id/targets`              | `TargetsResult`: progress of the site's goal targets in their own periods (admin only; takes no range)                                                              |
| `GET /sites/:id/realtime`             | `Realtime`: visitors in the last 5 minutes, recent events and their visits on the map                                                                               |
| `GET /sites/:id/sessions`             | `Page<SessionSummary>`, see [Lists](#lists)                                                                                                                         |
| `GET /sites/:id/sessions/:sid`        | One session with its visitor profile, events and payments (admin only)                                                                                              |
| `GET /sites/:id/events?name=&type=`   | `Page<EventRow>`, see [Lists](#lists)                                                                                                                               |
| `GET /sites/:id/payments`             | `Page<Payment>`, see [Lists](#lists) (admin only)                                                                                                                   |

Dimensions for `breakdown`: `channel`, `source`, `referrer`, `campaign`, `medium`, `term`, `content`, `ref`, `page`, `entry`, `exit`, `country`, `region`, `city`, `browser`, `os`, `device`, `event`, `outbound`, `goal`.

### Lists

Sessions, events and payments answer one page at a time, newest first: `{ items, nextCursor, total }`. `total` counts every match, not just this page.

| Parameter       | Meaning                                                                                             |
| --------------- | --------------------------------------------------------------------------------------------------- |
| `limit`         | Page size, up to 100.                                                                               |
| `cursor`        | The previous page's `nextCursor`. Only for the default order.                                       |
| `offset`        | Skip this many matches, for numbered pages. `nextCursor` is then `null`.                            |
| `sort`, `order` | Sort key and `asc` or `desc` (default `desc`). `nextCursor` is then `null`. Empty values sort last. |
| `search`        | Case-insensitive substring match over the list's text columns.                                      |
| `visitor`       | Only the rows of this visitor id.                                                                   |

Sort keys: sessions `time duration pageviews source country entry revenue`; events `time type name page`; payments `time amount provider customer attribution`. Sessions search pages, sources, channels, places, browsers, systems and visitor ids; events search names, paths and types; payments search ids, emails, names, customer, order and subscription ids and the provider.

Events also take `name` and `type` (`pageview`, `goal`, `outbound`, `revenue`, `identify`). Payments take `kind` (`payment` or `refund`), `provider` and `attributed` (`true` or `false`). An unknown sort, order or filter value answers 400, and so does a `cursor` combined with `sort` or `offset`.

```bash
curl -b cookies.txt \
  "https://analytics.example.com/api/sites/SITE_ID/payments?kind=refund&sort=amount&order=desc&offset=25&limit=25"
```

### Filters

Filters use the dimension names as query keys: `country=DE&channel=Organic%20Search&page=/pricing`. Repeat a key to match any of several values.

```bash
curl -b cookies.txt \
  "https://analytics.example.com/api/sites/SITE_ID/breakdown?dimension=source&from=2026-10-01&to=2026-11-01&country=DE"
```

### Share links

Admin routes, per site:

| Method and path                      | Description                                                                                                                                                                                                                                                                                  |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /sites/:id/share-links`        | Body: optional `label` (80 characters), `views` (any of `overview`, `sources`, `pages`, `events`, `sessions`, `bots`, `funnels`, `realtime`; empty means all) and `expiresInDays` (1 to 3650). Answers 201 `{ link, token }`. The token is shown only now. At most 50 active links per site. |
| `GET /sites/:id/share-links`         | `ShareLink[]`, newest first, revoked ones included, without tokens.                                                                                                                                                                                                                          |
| `DELETE /sites/:id/share-links/:lid` | Revokes the link at once. 404 for an unknown link.                                                                                                                                                                                                                                           |

A request that carries a token, as `?share=TOKEN` or an `x-analytik-share: TOKEN` header, can read these `GET` routes without logging in: `shared` (the site's name, domain, time zone and currency, and the link's views), `overview`, `timeseries`, `breakdown`, `realtime`, `sessions`, `events`, `bots`, and the funnel list and funnel results. A link limited to some views reads only the routes behind them; any other route answers 401, as does a token for another site, a revoked or an expired one. That is the aggregate numbers and the session list, including visitor ids, countries, cities, browsers, pages, referrers, and event names and properties. Payments, single-session details, the site settings, export and every write, including the share-link routes, stay admin only.

Only a token in the address is cached publicly: those answers carry `Cache-Control: public, s-maxage=60` (10 seconds for `realtime`). Tokens are stored as SHA-256 hashes.

The older single token still works: `PATCH /sites/:id` with `{ "shareToken": true }` returns a plain `shareToken` that opens every shareable route, uncached, until `{ "shareToken": null }`. Prefer share links.

### Maintenance

| Method and path                  | Description                                                                                                                                           |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /sites/:id/rematch`        | Retry attribution for payments without a match.                                                                                                       |
| `GET /sites/:id/export?format=`  | `json`: everything for the site in one file. `csv`: one table at a time, chosen with `table=visitors\|sessions\|events\|payments` (default `events`). |

### Debug

Test data for trying the dashboard with many sites, long histories and large numbers. `GET /debug` always answers; the other routes answer 404 unless the server was created with `debug: true`.

| Method and path        | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /debug`           | `{ enabled }`: whether the debug routes are on.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `POST /debug/generate` | Writes made-up visits, events, goals and payments (`TestDataInput`). With `siteId` they go into that site; otherwise into `sites` new sites with ids starting `debug-`. `days` (0 to 730), `visitorsPerDay` (0 to 100,000; a zero in either makes empty sites), `priceScale` and `currency` set the amounts. With `mix: true` the new sites differ the way real ones do (an empty one, a quiet blog, a busy shop, one just launched, a paused one and more), and `visitorsPerDay` and `priceScale` don't apply. One call writes at most 1,000,000 visits. Answers with `TestDataResult`: the sites, counts and how long it took. |
| `DELETE /debug/sites`  | Deletes every site whose id starts with `debug-`, with its data. Answers `{ deleted }`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

### Payments

`POST /v1/payments` and `analytik.recordPayment()` take a `PaymentInput`. Amounts are minor units. A refund has `kind: "refund"` and the positive amount. For a refund without an id of its own, send `refundedTotal`, the total refunded for the order so far, and the server records only the difference; a retried request adds nothing.

Revenue events from the tracker are stored as payments with the provider `client` and the id `client:<orderId>`. When a verified payment from a provider webhook or your server arrives for the same order, it replaces the client record instead of counting twice.
